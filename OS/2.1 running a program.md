# How a Program Runs on a CPU

## Memory Layout of a Running Process

A **process** is loaded entirely into memory when it starts executing.

The memory is organized into distinct regions:
- **Text/Code Segment**: Contains the machine instructions. This is **read-only** and cannot be modified during execution.
  - *Exception*: In **JIT (Just-In-Time) compilation** languages like JavaScript and Java, compiled code is generated at runtime and stored in the **heap** (writable memory), not the text segment.

- **Data Segment**: Global and static variables
- **Heap**: Dynamically allocated memory
- **Stack**: Function calls, local variables, and return addresses

## CPU Core Allocation

Typically, **1 CPU core is allocated to a process** for execution. The OS scheduler ensures that processes get time slices on available cores.

**Exception**: **Hyperthreading (Intel) or SMT (Simultaneous Multithreading)** creates logical/virtual cores that share a single physical core's resources. This allows the CPU to process two instruction streams concurrently.

## Memory Hierarchy & Access Latency

Understanding access times helps explain why caches are critical for performance:

| Storage Level | Access Time | Notes |
|---|---|---|
| **Registers** | 1 ns | CPU's fastest storage (limited in count) |
| **L1 Cache** | 2 ns | Per-core, smallest cache |
| **L2 Cache** | 7 ns | Per-core or shared |
| **L3 Cache** | 15 ns | Shared among cores on same CPU |
| **RAM (Main Memory)** | 100 ns | System memory (50-100x slower than registers) |
| **SSD** | 150 µs | Disk storage (1000x slower than RAM) |
| **HDD** | 10 ms | Traditional hard disk (100,000x slower than RAM) |

**Key Insight**: A single memory access can cost as much as executing millions of CPU operations. Caches exist to minimize these expensive memory trips.

## The CPU Instruction Execution Cycle

When a program starts, the CPU follows this core cycle repeatedly:

### Step 1: Fetch the Address
- The **Program Counter (PC)** register holds the memory address of the next instruction to execute.
- The **ELF header** (or other executable format) tells the OS where the first instruction is located.
- The PC is set to this address initially.

### Step 2: Fetch the Instruction
- The CPU reads from the memory address stored in the PC (a **memory read** operation).
- The instruction is loaded into the **Instruction Register (IR)**.
- Due to **caching**, if the instruction was recently accessed, it's fetched from L1 cache (2 ns) instead of main memory (100 ns) — a 50x speedup!

### Step 3: Decode & Execute
- The CPU decodes what the instruction means (e.g., "add two numbers", "load from memory").
- The instruction is executed in the CPU's ALU (Arithmetic Logic Unit) or other execution units.

### Step 4: Increment Program Counter
- After execution, the PC is incremented by the **instruction size**:
  - **32-bit systems**: PC += 4 bytes
  - **64-bit systems**: PC += 8 bytes
- This points to the next instruction in sequence.

### Step 5: Write Results Back
- If the instruction produces a result (e.g., from a calculation), it must be stored in memory.
- Writes also go through the **cache hierarchy**: L1 → L2 → L3 → Main Memory.
- This is called **write-through** or **write-back** depending on the cache policy.

## Why Caches Matter

**Without caches**: Every instruction and data access would require 100+ ns from main memory. Modern programs do billions of operations per second — you'd spend most time waiting for memory!

**With caches**: 
- **Spatial Locality**: When you access address X, nearby addresses are likely needed soon. Caches prefetch them.
- **Temporal Locality**: If you accessed address X recently, you'll likely access it again soon. Caches keep it handy.

Most memory accesses hit L1 cache, reducing average access time to ~2-10 ns instead of 100+ ns.

---

## Summary: The Complete Picture

1. **Process loads** into memory with code in the text segment
2. **CPU core** is assigned to the process
3. **Program Counter** initialized to first instruction address (from ELF header)
4. **Fetch-Decode-Execute cycle** repeats:
   - Fetch instruction from address in PC (via cache)
   - Decode and execute
   - Increment PC
   - Write results back (via cache)
5. **Caches** make this loop fast by storing recently-used instructions and data
6. **Program continues** until it terminates or is interrupted by the OS
