# What is Heap Memory?

- Heap is the memory region used for:
  - Dynamic memory allocation
  - Large data
  - Data structures like:
    - Linked Lists
    - Trees
    - Objects
    - Arrays
  - Runtime/JIT generated code

- Heap grows:
  - Low → High memory addresses

- Unlike stack:
  - Memory is not automatically cleaned
  - Must be explicitly freed

---

# Stack vs Heap

| Stack | Heap |
|---|---|
| Fast | Slower |
| Automatic cleanup | Manual cleanup |
| Function-local data | Dynamic/shared data |
| High → Low growth | Low → High growth |
| Cache friendly | Random memory layout |
| Limited size | Larger size |

---

# Why Heap Exists

Heap is needed when:

- Data must survive after function calls
- Data is shared across functions
- Data size is unknown at compile time
- Large allocations are required

Example:
```c
int* arr = malloc(1000 * sizeof(int));
```

---

# Heap Allocation

## malloc()

Allocates memory in heap.

```c
int* p = malloc(sizeof(int));
```

### What happens internally?

1. Program switches to kernel mode
2. OS allocates memory
3. Returns pointer to allocated memory

---

## free()

Releases heap memory.

```c
free(p);
```

Important:
- `free()` only needs pointer
- Allocator stores metadata/header internally

---

# Pointer Basics

## Pointer

A pointer stores:
- Memory address

Example:
```c
int *p;
```

### Important

- Pointer itself has size:
  - 4 bytes in 32-bit
  - 8 bytes in 64-bit

- Pointer can live in:
  - Stack
  - Heap
  - Data section

---

# Example Flow

```c
int* p = malloc(sizeof(int));
*p = 10;
*p = *p + 1;
free(p);
```

### Steps

1. Allocate heap memory
2. Store address in pointer
3. Write value to heap
4. Modify value
5. Free memory

---

# Memory Leak

## Definition

Memory allocated but no pointer references it.

Example:
```c
void func() {
    int* p = malloc(sizeof(int));
}
```

Problem:
- Function exits
- Pointer destroyed
- Heap memory still allocated

Result:
- OS thinks process still uses memory

---

# Garbage Collection

Languages like:
- Java
- C#
- Go

use:
- Garbage Collection (GC)
- Reference Counting

GC checks:
- Whether memory is still referenced

If no references exist:
- Memory can be reclaimed

---

# Dangling Pointer

## Definition

Pointer refers to memory already freed.

Example:
```c
free(p);
*p = 5; // dangerous
```

Possible results:
- Garbage data
- Crash
- Segmentation fault

---

# Double Free

## Definition

Freeing same memory twice.

Example:
```c
free(p);
free(p);
```

Can cause:
- Crashes
- Security vulnerabilities
- Denial of Service

---

# Heap Performance Issues

## Heap is slower because:

### 1. Kernel Mode Switch
`malloc/free` require OS interaction.

### 2. Metadata Overhead
Each allocation stores headers.

### 3. Random Memory Layout
Poor cache locality.

---

# Stack Performance Advantage

Stack is faster because:

- Automatic cleanup
- Contiguous memory
- Better CPU cache utilization

---

# Cache Locality

CPU reads memory in chunks:
- Typically 64-byte cache lines

If related data is nearby:
- Faster access

If data is scattered:
- More cache misses
- Slower performance

---

# Important Optimization

## Structure Reordering

Linux kernel improved TCP/IP performance by:
- Rearranging structure variables

Reason:
- Frequently accessed fields placed together
- Better cache locality

Result:
- ~40% performance improvement

---

# Escape Analysis (Go)

Compiler optimization.

If compiler detects:
- Heap allocation does not escape function

Then:
- Allocation moved to stack

Benefits:
- Faster allocation
- Automatic cleanup

---

# Program Break

Heap top tracked using:
- `brk`
- `sbrk`

Modern systems mostly use:
- `mmap()`

instead of direct `brk/sbrk`.

# Important Interview Points

## Why is stack faster than heap?

- No manual management
- Better cache locality
- No kernel allocation overhead

---

## What causes memory leaks?

- Allocating memory without freeing it

## Difference between memory leak and dangling pointer

| Memory Leak | Dangling Pointer |
|---|---|

# Java Memory Model

Java memory is mainly divided into:

| Memory Area | Purpose |
|---|---|
| Heap | Objects and instance variables |
| Stack | Method calls, local variables |
| Metaspace | Class metadata |
| PC Register | Current instruction tracking |

---

# Heap in Java

## What goes into Heap?

- Objects
- Arrays
- Instance variables

Example:
```java
Person p = new Person();
```

- `p` → stored in stack
- `new Person()` object → stored in heap

---

# Garbage Collection (GC)

Java automatically frees unused objects.

Example:
```java
Person p = new Person();
p = null;
```

Now object becomes:
- Eligible for garbage collection

Important:
- GC is automatic
- But not immediate

---

# Memory Leak in Java

Java can still have memory leaks.

Example:
```java
List<Object> list = new ArrayList<>();

while(true){
    list.add(new Object());
}
```

Result:
```text
OutOfMemoryError
```

---

# Heap Generations

Java heap divided into:

| Region | Purpose |
|---|---|
| Young Generation | New objects |
| Old Generation | Long-lived objects |
| Metaspace | Class metadata |

---

# Stack Overflow vs Heap Overflow

## Stack Overflow

```java
void recurse(){
    recurse();
}
```

Causes:
```text
StackOverflowError
```

---

## Heap Overflow

```java
while(true){
    list.add(new byte[1024 * 1024]);
}
```

Causes:
```text
OutOfMemoryError: Java heap space
```

---

# String Pool

Java optimizes strings using:
- String Constant Pool

Example:
```java
String a = "hello";
String b = "hello";
```

Both point to same object.

---

# Escape Analysis in Java

JVM optimization similar to Go.

If object does not escape method:
- JVM may allocate on stack
- Avoid heap allocation

Benefits:
- Faster execution
- Less GC pressure

---

# Best Practices in Java

- Reuse objects when possible
- Avoid unnecessary object creation
- Clear collections after use
- Use StringBuilder instead of repeated String concatenation

---

# Final Summary

- Heap stores dynamic data
- Heap memory must be manually managed in C/C++
- Java uses Garbage Collection
- Stack is faster due to:
  - Better locality
  - Automatic cleanup

- Modern languages use:
  - Garbage collection
  - Escape analysis
  - Smart allocators
