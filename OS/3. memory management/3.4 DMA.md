# DMA (Direct Memory Access)

DMA is a hardware feature that allows a device to transfer data directly between I/O devices and physical memory without continuous CPU intervention.

## Why DMA is needed

- In traditional programmed I/O, the CPU reads data from the device and writes it to memory one word at a time.
- Each device transfer generates interrupts and consumes CPU cycles.
- For large data transfers (disk, network, graphics), this overhead becomes inefficient.

## How DMA works

- A DMA controller is a separate hardware unit connected to the system bus.
- The CPU programs the DMA controller with:
  - source physical address
  - destination physical address
  - transfer size
  - transfer direction (device → memory or memory → device)
- The DMA controller takes control of the bus, performs the transfer, and then signals the CPU when the transfer completes.

## CPU vs DMA transfer

1. CPU-driven I/O
   - CPU reads from device registers
   - CPU writes to memory
   - Many interrupts or polling operations
   - High CPU overhead

2. DMA-driven I/O
   - CPU initiates transfer and then continues other work
   - DMA controller moves data directly
   - CPU is interrupted only at completion or on error
   - Lower CPU overhead for large transfers

## DMA and memory addressing

- DMA transfers normally use physical addresses because the DMA controller does not perform virtual address translation.
- The CPU uses virtual addresses, while DMA uses physical addresses.
- Therefore, the memory region used by DMA must be pinned and mapped to physical memory.

### IOMMU

- An IOMMU (Input/Output Memory Management Unit) enables DMA to use virtual addresses.
- It translates device-generated addresses to physical addresses, similar to how the CPU MMU translates virtual addresses.
- IOMMU also provides protection by isolating DMA devices from accessing arbitrary physical memory.

## `O_DIRECT` and direct I/O

- `O_DIRECT` is a file I/O mode in Linux that instructs the kernel to bypass page cache for a file transfer.
- It is often used by databases and file systems to reduce double buffering and improve throughput.
- `O_DIRECT` may still use DMA for the underlying device transfer.
- Benefits include fewer copies and reduced cache pollution.

## Advantages of DMA

- More efficient data transfer for large blocks of data.
- Reduces CPU usage during I/O operations.
- Improves throughput for devices like disks, network cards, and GPUs.

## Disadvantages and challenges

- DMA requires physical memory buffers and careful memory management.
- Not all devices support DMA for small or latency-sensitive I/O like keyboard/mouse events.
- DMA can introduce security risks if devices are allowed to access arbitrary physical memory.
- Without an IOMMU, DMA-capable devices may be vulnerable to DMA attacks.

## Use cases

- Disk controllers copying file data to memory.
- Network cards transferring packets to/from memory.
- Graphics cards moving frame buffers.
- Storage devices and high-speed peripherals.

## Key points

- DMA reduces CPU work by handling data movement between devices and RAM.
- It relies on physical addresses unless an IOMMU is present.
- It is most effective for large, sequential transfers rather than frequent small events.
