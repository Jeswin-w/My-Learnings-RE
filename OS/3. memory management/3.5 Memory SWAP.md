# Memory Swap

## What is swap?

Swap is the system's ability to extend virtual memory beyond physical RAM by using disk storage. When physical memory becomes full, the OS moves infrequently accessed pages from RAM to disk, freeing RAM for other processes.

## How swap works

1. **Page eviction**: OS identifies candidate pages (usually based on least recently used or other page replacement algorithms).
2. **Write to disk**: Selected pages are written to swap space on disk.
3. **Page table update**: The page table entry is marked as "not present" or "swapped out," pointing to the disk location.
4. **Page fault on access**: If the process later accesses a swapped-out page, a page fault is triggered.
5. **Page restoration**: The OS reads the page from disk back into RAM (possibly evicting another page), updates the page table, and resumes the process.

## Page faults and swap

A page fault occurs when:
- A process accesses a virtual address that is not currently in physical RAM.
- The page is either:
  - Not yet allocated (virgin page, zeroed on demand)
  - Swapped out to disk
  - In a region protected or not yet mapped

## Translation Lookaside Buffer (TLB)

The TLB is a small, fast cache inside the CPU that stores recent virtual-to-physical address translations.

### How TLB works

- Each virtual memory access checks the TLB first.
- TLB hit: The physical address is found immediately (very fast).
- TLB miss: The CPU must walk the page table to find the translation, which is slower.

### TLB and swap

- When a page is evicted to swap, its page table entry changes (marked as invalid/swapped).
- When that page is later accessed, the TLB entry is stale if it still holds the old translation.
- The hardware or OS must invalidate TLB entries when pages are swapped out.
- This adds to the cost of page faults; the TLB must be flushed or updated.

### TLB invalidation

- **Local invalidation**: Clear TLB entries for specific virtual addresses (more efficient).
- **Global invalidation**: Flush the entire TLB when a page table changes significantly.
- On multi-core systems, TLB shootdown ensures all cores invalidate the relevant entries.

### TLB and context switching

Context switching occurs when the OS switches execution from one process or thread to another.

#### Process switching

- Each process has its own virtual address space and page table.
- When switching processes, the hardware updates the **page table base register** (PTBR) to point to the new process's page table.
- The TLB becomes stale after process switch because the old translations map to the previous process's virtual addresses.
- The OS must flush the entire TLB or tag each entry with a process ID (ASID - Address Space ID).

**Two flushing strategies:**

1. **Flush entire TLB**: Simple but costly; all cached translations are lost, resulting in TLB misses until the new process rebuilds cache.
2. **Use ASID (Address Space Identifier)**: Modern CPUs tag TLB entries with a process ID, allowing entries from multiple processes to coexist without flushing. The CPU only uses entries matching the current ASID.

#### Thread switching

- Threads within the same process share the same virtual address space and page table.
- When switching between threads in the same process, the page table remains unchanged.
- The TLB does **not** need to be flushed because both threads use the same virtual-to-physical translations.
- Thread switching is therefore much cheaper than process switching from a memory perspective.

**Key difference:**
- Process switch → TLB flush/ASID change → TLB cache invalid
- Thread switch → No TLB invalidation → Translations remain valid

#### Cost of context switching

- Process switching: Typically costs 1,000–10,000 CPU cycles due to TLB and cache invalidation.
- Thread switching: Typically costs 100–1,000 CPU cycles (no TLB invalidation needed).
- This is one reason why threads are preferred over processes for fine-grained concurrency.

## Swap space setup

- On Linux, swap space can be a dedicated partition or a swap file on the file system.
- Multiple swap regions can be configured for redundancy.
- Swap priority determines which devices are used first.

## When is swap triggered?

- When available physical memory falls below a threshold.
- When a process requests memory and free pages are not available.
- The kernel typically uses background threads to preemptively swap pages before memory is critically full.

## Performance impact

Swap significantly slows down memory access:
- Disk access is 1,000–10,000 times slower than RAM access.
- Heavy swapping causes "thrashing"—the system thrashes when most time is spent swapping rather than executing programs.

Recommendations:
- Minimize swap by having sufficient RAM for typical workloads.
- Enable swap as a fallback to prevent out-of-memory errors, but avoid relying on it.
- Monitor swap usage; consistently high usage indicates a need for more RAM or process optimization.

## Swap configuration

- `swappiness` parameter (Linux): Controls the tendency to swap; values 0–100, where 100 means swap aggressively and 0 means avoid swapping.
- `vm.swappiness = 0` is sometimes used to disable swap, though the kernel may still swap in emergencies.
- `vm.swappiness = 10` is typical for servers requiring low latency.

## Advantages of swap

- Allows the system to recover from temporary memory pressure.
- Prevents out-of-memory killer from terminating processes.
- Enables running more processes than physical RAM alone allows.

## Disadvantages of swap

- **Performance degradation**: Page faults and disk I/O are slow.
- **I/O stress**: Heavy swapping creates disk bottlenecks.
- **Unpredictability**: Application latency becomes highly variable.
- **SSD wear**: On SSDs, frequent swapping can reduce device lifespan.

## Key points

- Swap extends virtual memory to disk, providing a safety net when RAM is full.
- Page faults trigger costly disk I/O and TLB invalidation.
- TLB caching and invalidation are overhead costs of swap.
- Swap should be used sparingly; sufficient RAM is preferred for predictable performance.
