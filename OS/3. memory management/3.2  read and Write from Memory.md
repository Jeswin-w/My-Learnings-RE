## Read / Write to Memory

### Key Points

- Memory access is expensive in the worst case: around **100 ns** for a DRAM read/write miss.
- DRAM works in **rows**: a single read fetches a burst (commonly **64 bytes**), not just one byte.
- **Locality is critical**: if the next instruction/data is in that fetched block, CPU cache (L1) serves it much faster (~1–2 ns).
- **Sequential access** patterns are fast; random jumps in code/data cause repeated cache misses and high latency.
- **Virtual → physical address translation** happens via the CPU + MMU (memory management unit), which uses the page table. CPU deals only with virtual addresses.
- **DDR5 vs DDR4**: DDR5 is not faster for one isolated request; its main advantage is higher **concurrency/parallelism** when multiple requests hit different channels. DDR4 blocks concurrent access to the same bank/region (~100 ns block).
