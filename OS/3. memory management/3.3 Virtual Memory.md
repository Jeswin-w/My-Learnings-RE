# Virtual Memory

Virtual memory is an abstraction that gives each process the illusion of a large, contiguous address space independent of the actual physical RAM.

## Why virtual memory is needed

- Physical RAM is limited and processes may require more memory than available.
- Physical memory becomes fragmented over time as processes allocate and free memory.
- Without virtual memory, each process would need contiguous physical memory, making allocation harder and reducing utilization.

### Fragmentation

- External fragmentation: free memory exists, but it is split into small non-contiguous blocks, so a large allocation cannot be satisfied.
- Internal fragmentation: allocated memory blocks are larger than the data stored in them, wasting space inside each block.

Virtual memory reduces the need for large contiguous physical allocations by mapping process memory in fixed-size units.

## Paging

Paging divides both virtual memory and physical memory into fixed-size blocks called pages.

- Common page size is 4 KB, though it can be larger (2 MB, 1 GB) with hugepages.
- A process sees a virtual address space made of virtual pages.
- The OS maps each virtual page to a physical frame in RAM.

This mapping means:
- A process can use virtual pages that are not currently in physical RAM.
- Virtual pages do not need to be stored contiguously in physical memory.
- Many virtual pages can be mapped to the same physical page for shared code or read-only data.

## Virtual address translation

A CPU-generated virtual address is split into:
- Virtual page number (VPN)
- Offset within the page

The operating system keeps a page table for each process.

### Page table

- The page table stores the physical frame number (PFN) corresponding to each VPN.
- If a virtual page is not present in RAM, the page table marks it as invalid or swapped out.
- The page table may also contain permission bits: read, write, execute, user/supervisor.

Example:
- 32-bit virtual address, 4 KB pages → 20-bit VPN + 12-bit offset.
- 64-bit systems use much larger virtual spaces, but the basic translation idea is the same.

## Translation Lookaside Buffer (TLB)

- The TLB is a small cache inside the CPU that stores recent virtual-to-physical translations.
- A TLB hit avoids a full page table lookup and is much faster.
- A TLB miss requires walking the page table, which the CPU or OS performs.

## Shared pages and memory

### Shared code and libraries

- When the same program or library is loaded multiple times, the OS can map the same physical pages into different processes' virtual address spaces.
- This saves memory by sharing read-only code or data between processes.

### Shared memory regions

- Processes can also explicitly share memory regions for fast communication.
- Shared pages remain in physical memory and are mapped into multiple virtual address spaces.

## Copy-on-write (COW)

- Copy-on-write delays copying memory until one of the processes modifies it.
- For example, `fork()` creates a child process with the same virtual pages as the parent, marked read-only.
- If either process writes to a shared page, the OS makes a private copy for that process.
- This avoids duplicating memory unnecessarily at process creation.

## Isolation and protection

Virtual memory provides process isolation:
- Each process only sees its own virtual addresses.
- A process cannot directly access another process's physical memory.
- The CPU and OS enforce this through page table permissions and address translation.

This improves security and prevents accidental or malicious access to other processes' data.

## Swapping and page faults

When physical memory is full, the OS may move infrequently used pages to disk (swap or page file).

- This is called swapping or paging out.
- If a process later accesses a swapped-out page, a page fault occurs.
- The OS handles the fault by loading the page from disk back into RAM and updating the page table.

Tradeoffs:
- Swapping increases available virtual memory beyond physical RAM.
- Disk access is slow, so swapping can reduce performance if it happens too often.

## Benefits of virtual memory

- Simplifies memory management by presenting each process with a full address space.
- Enables more processes to run than physical RAM alone would allow.
- Helps protect processes from each other.
- Allows sharing of code and libraries.
- Supports features like copy-on-write and memory-mapped files.

## Limitations and costs

- Address translation adds overhead and requires page table lookups.
- TLB misses and page faults can slow execution.
- Managing page tables and swapping consumes kernel resources.
- Kernel must maintain page tables, handle faults, and enforce permissions.

## Key terms

- Virtual address: address used by a process.
- Physical address: actual location in RAM.
- Page: fixed-size block of virtual memory.
- Frame: fixed-size block of physical memory.
- Page table: data structure mapping pages to frames.
- TLB: cache of recent translations.
- Page fault: exception raised when a page is not currently in RAM.
- Swap: disk space used to store pages evicted from RAM.
