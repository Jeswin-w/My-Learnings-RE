If a class is public, don't give it public fields; use private fields and provide accessors instead.

Notes — Use accessors, not public fields
- **Encapsulation:** Making fields private preserves invariants and hides implementation details.
- **Flexibility:** Accessors let you change the internal representation later without breaking callers.
- **Validation & Control:** Getters/setters (or only getters) allow validation, lazy initialization, and controlled mutation.
- **Defensive copies:** For mutable objects (including arrays), return defensive copies or immutable views from accessors to avoid exposing internal state.
- **Immutable/public constants:** Prefer private `static final` fields with accessors for mutable types; expose only immutable objects directly.
- **API and binary compatibility:** Replacing a public field with methods is a breaking change; starting with accessors preserves the ability to evolve APIs safely.
- **Thread-safety & documentation:** Accessors provide a place to document and enforce synchronization, or to return immutable snapshots for safe concurrent use.
- **Minimal surface area:** Avoid unnecessary setters; expose only what's required (prefer read-only access when possible).

Practical tips
- Prefer immutable classes where possible so accessors can safely expose fields.
- When exposing collections, return unmodifiable views or copies: `Collections.unmodifiableList(new ArrayList<>(list))`.
- For arrays, always return `Arrays.copyOf(array, array.length)` from getters.
- Document the mutability and thread-safety guarantees of accessors in the public API.

Summary: Keep fields private in public classes. Use accessors to control exposure, preserve invariants, and retain the freedom to change implementations later.
